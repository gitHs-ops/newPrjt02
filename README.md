# newPrjt02

빌드 단계가 없는 **정적 HTML 앱** 두 벌.

1. **로그인 데모** — 계정은 브라우저 `localStorage` 에만 저장하는 테스트용이며,
   비밀번호는 평문이 아니라 **PBKDF2-SHA256(10만회) + 사용자별 랜덤 솔트** 해시로 보관한다.
2. **진로상담 분석** — 중·고 진로교사용. 학생 정보로 **1차 진로·산업·진학 리서치**,
   추가 경험·학교자료를 더해 **2차 진로 가설 분석**까지 이어간다.
   로그인 성공 화면(`home.html`)에서 진입한다.

> **이 앱은 AI 를 대신 부르지 않는다.**
> 프롬프트를 조립해 주고, 받은 결과를 보관·렌더한다. 그 사이는 사람이 한다.

## 진로상담이 도는 방식

```
[앱]   학생 정보 입력 → 프롬프트 전문 조립 → 클립보드로 복사
                              ↓
[사람] 원하는 AI 화면(Claude · ChatGPT …)에 붙여넣고 실행
                              ↓
[앱]   받은 md 를 되돌려 넣기 → 완결성 검사 → 렌더 → 사례에 보관 → md 저장
```

**API 키·프록시 배포·요금·실행시간 한도가 존재하지 않는다.** 브라우저와 프롬프트 원문뿐이다.
어떤 AI 를 쓸지도 교사가 그때그때 고르면 된다.

대가는 하나 — **사람 손이 경로에 들어온다.** 스크롤 중간에서 복사하거나 전체 선택에
실패하면 보고서가 잘린다. 그래서 붙여넣는 즉시 **완결성 검사**가 돈다(아래 참고).

> 2026-09-02 이전에는 Apps Script 프록시를 경유해 앱이 직접 AI 를 호출했다.
> 그 코드는 폐기했고, 경위는 `claude-progress.md` 의 Session 007~011 에 있다.

## 실행

```powershell
.\init.ps1 -Start
```

→ http://localhost:8941/

| 옵션 | 동작 |
|---|---|
| `.\init.ps1` | 검증만 수행 (76개 항목) |
| `.\init.ps1 -Live` | + 배포된 프록시까지 확인 (careerTest·시트용, 진로상담과 무관) |
| `.\init.ps1 -Start` | 검증 후 로컬 서버 기동 |
| `.\init.ps1 -Start -OpenBrowser` | 기동 후 브라우저까지 열기 |
| `-Port 9000` | 포트 변경 (기본 **8941**) |

> ⚠ `init.ps1` 은 **UTF-8 BOM** 으로 저장해야 한다. BOM 이 없으면 Windows PowerShell 5.1 이
> cp949 로 읽어 한글이 깨지고 파서 오류가 난다.

> ⚠ `file://` 로 직접 열면 동작하지 않는다. Web Crypto(비밀번호 해싱)가 보안 컨텍스트를
> 요구하고, 프롬프트 원문도 `fetch` 로 읽기 때문이다. 반드시 로컬 서버로 띄운다.

| `career-report2.html` | 2차 결과 **붙여넣기** → 저장 → md 저장 · **1·2차 합본 저장** |

프롬프트 원문은 `fetch` 로 **직접 읽는다.** 생성물(`career-prompts.js`)을 두지 않으므로
"원문을 고치고 생성기를 안 돌려 낡은 프롬프트가 나가는" 사고가 구조적으로 없다.
(`init.ps1` 이 그 생성물이 되살아나면 실패시킨다.)

### 입력에서 손대지 않은 것 / 손댄 것

| 항목 | 처리 | 이유 |
|---|---|---|
| **희망 직업·직무** | 자유입력 그대로 | 프롬프트가 *"학생이 말한 표현"* 자체를 해석 대상으로 삼는다 |
| 학교급 → 성적 표기 | 중학교면 **성취도 A~E**, 고등학교면 **내신 등급** 으로 선택지가 바뀜 | 손으로 넣다 어긋나면 프롬프트가 `[확인 필요]` 로 되돌린다 |
| 진학 예정 연도 | 학년에서 자동 계산 (고2 → 2028) | 위와 같은 이유. 실제로 "중2인데 2등급 / 진학 2028년" 모순이 난 적 있다 |

### 완결성 검사

붙여넣는 즉시 보고서가 끝까지 왔는지 본다.

| 차수 | 기대 형식 |
|---|---|
| 1차 | A~L 12섹션 + 출처 구분 3소제목 + 면책 문장 |
| 2차 | STEP 1~11 + 면책 문장 |

면책 문장은 **있기만 해선 부족하고 문서 끝(마지막 25줄) 안**에 있어야 한다 —
중간에 있으면 뒤쪽이 잘린 것이다. 3,000자 미만, 깨진 문자(U+FFFD), 종류 판별 불가도 잡는다.

> **경고가 떠도 저장은 막지 않는다.** 잘린 보고서라도 남겨 둘 이유가 있고, 판단은 교사 몫이다.
> 대신 토스트에 무엇이 빠졌는지 함께 띄운다.

같은 검사를 **저장된 md 파일**에도 돌릴 수 있다:

```bash
python tools/check-report.py <보고서.md>
```

> ⚠ 기대 형식이 `assets/career.js` 와 `tools/check-report.py` **두 곳**에 있다.
> 갈라지면 한쪽만 통과하는 보고서가 생겨 검사 자체를 믿을 수 없게 되므로,
> `init.ps1` 이 공통 기대값 5종을 대조해 갈라짐을 잡는다.
> 프롬프트의 A~L / STEP 구조를 바꾸면 **세 곳을 함께** 고쳐야 한다.

## 데이터

| 키 | 저장소 | 내용 |
|---|---|---|
| `np_users` | `localStorage` | 계정 목록 — `id`, `salt`, `hash`, `provider`, `createdAt` |
| `np_session` | 상태유지 켬 → `localStorage`<br>끔 → `sessionStorage` | `id`, `provider`, `remember`, `loginAt` |
| `np_career_cases` | `localStorage` | 상담 사례 — `label`, `owner`, `student`, `report1`, `extra2`, `report2` |

보고서 레코드에는 `source: 'paste'` 가 남는다 — 사람 손에서 온 것임을 기록으로 구분한다.

초기화: 개발자도구 콘솔에서
`localStorage.removeItem('np_users')` / `localStorage.removeItem('np_career_cases')`

> 사례 이름은 **AI 로 전달되지 않는** 로컬 라벨이다. 학생 실명 대신 별칭을 쓸 것.
> 학교자료 입력란에 개인식별정보·민감정보를 넣지 말 것.

## 한계 (실서비스로 쓰기 전에 반드시 해결)

- **인증이 전부 클라이언트 측이다.** `home.html` 의 접근 제어는 가드일 뿐 보안 경계가 아니다
- **계정·사례가 브라우저별로 격리된다.** 다른 기기·브라우저·시크릿창에서는 보이지 않는다
- **Google 로그인은 실제 OAuth 가 아니다.** 흐름만 재현한 모의 동작이다
- **공식자료 웹검색이 앱 밖으로 나갔다.** 프롬프트는 커리어넷·KOSIS 같은 공식자료 확인을
  전제로 씌어 있다. 검색을 켤지는 **교사가 쓰는 AI 화면에서 정해진다** —
  검색 없이 돌리면 "확인 불가"가 대량으로 나온다
- 옵시디언 전송은 새 버전에 **아직 없다** (`career-009` 는 `retired`).
  연결 진단 도구 `tools/obsidian-check.html` 는 남아 있다

→ 남은 과제는 `feature_list.json` 참고. 보류: `auth-006`(서버 인증) · `auth-007`(실제 OAuth).

## 남겨 둔 인프라 — careerTest 공용

`tools/career_proxy.example.gs` 와 구글시트 기록은 **지우지 않았다.**
진로상담 앱은 더 이상 부르지 않지만, 형제 프로젝트 `careerTest` 가 같은 Apps Script
배포의 `GET` 경로를 계속 쓴다.

> ⚠ `.gs` 의 `doGet` 을 지우면 careerTest 가 죽는다.
> 배포는 **배포 관리 → 편집 → 새 버전** 으로 한다("새 배포"는 `/exec` URL 이 바뀐다).
> `.\init.ps1 -Live` 가 배포본 버전을 실제로 조회해 대조한다.

## 에이전트 하네스

이 저장소는 장시간 에이전트 작업을 전제로 구성돼 있다.

| 파일 | 역할 |
|---|---|
| `AGENTS.md` / `CLAUDE.md` | 에이전트 운영 지침 |
| `init.ps1` | 표준 시작·검증 경로 (테스트 러너) |
| `feature_list.json` | 기능 상태의 단일 원본 |
| `claude-progress.md` | 세션 진행 로그 |
| `session-handoff.md` | 세션 간 인계 노트 |

세션을 시작할 때는 `session-handoff.md` → `claude-progress.md` → `feature_list.json`
순으로 읽고 `.\init.ps1` 을 실행한다.

폐기한 기능은 지우지 않고 **`retired`** 상태 + evidence 로 남긴다 —
다시 만들 때 무엇을 만족해야 하는지가 거기 있다.
